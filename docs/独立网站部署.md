# ord. 独立网站部署

此方案运行普通 Node.js 服务，不依赖 ChatGPT Sites 或 ChatGPT 登录。已选定 Render 免费 Web Service，部署配置见根目录 `render.yaml`。当前等待完成平台登录、仓库授权和首次部署，尚无已验证的线上地址。详细操作见 [Render 部署](Render部署.md)。

## 本地开发

```sh
npm run dev -- --port 5173
```

访问 http://127.0.0.1:5173/。继续使用同一个浏览器和地址，可以读取原有本地词库。

## 构建独立版本

需要 Node.js 24 或更高版本：

```sh
npm ci
npm run build:standalone
npm run verify:standalone
cd standalone
npm start
```

生成的 `standalone/` 包含前端和服务端，无需在运行服务器上安装项目依赖，也不包含本机 `.env.local` 或个人词库备份。运行时使用环境变量设置 AI 服务。不能使用仅托管静态文件的平台，因为 AI 整理需要服务端接口。

## 托管设置

可使用支持 Docker 的托管服务或自己的服务器。仓库根目录提供 Dockerfile；容器默认监听 8080，支持平台注入的 PORT，健康检查地址为 `/healthz`。

在托管服务中设置这些环境变量，不要提交到 Git：

| 变量              | 设置方式                                                     |
| ----------------- | ------------------------------------------------------------ |
| `HOST`            | `0.0.0.0`，Docker 中已默认设置                               |
| `PORT`            | 平台指定的端口，Docker 默认 8080                             |
| `PUBLIC_ORIGIN`   | 实际独立网址，例如 `https://words.example.com`，不要附加路径 |
| `SITE_PASSWORD`   | 为个人网站设置的访问密码；用户名固定为 `ord`                 |
| `OPENAI_API_KEY`  | AI 服务密钥，仅保存在服务端                                  |
| `OPENAI_MODEL`    | 与本机已验证的模型配置保持一致                               |
| `OPENAI_BASE_URL` | 与本机模型服务配置保持一致                                   |
| `AI_API_STYLE`    | `responses` 或 `chat`，取决于模型服务                        |

外网监听要求设置网站来源和 SITE_PASSWORD。Render 会自动提供实际分配的 RENDER_EXTERNAL_URL，因此首次部署无需手工填写 PUBLIC_ORIGIN；以后绑定自己的域名时再设置 PUBLIC_ORIGIN。通过托管平台的 HTTPS 地址访问，或由自己的 HTTPS 反向代理转发到容器。个人版使用浏览器的用户名和密码提示框，不提供多人注册；健康检查不需要密码。AI 仅接受当前网站来源的请求，保留请求大小、频率及并发限制。

本地开发无需网站密码。只有明确在本机配置 SITE_PASSWORD 时才会启用密码提示。

## 词库迁移与保存边界

当前版本的词库和学习进度仍在浏览器 IndexedDB 中。独立托管与云端词库是两件事：完成网站部署，不会自动增加账号、数据库或跨设备同步。

迁移时，从本地导出完整 JSON；在新的独立网址使用「数据与设置 → 合并导入备份」，避免覆盖已有内容。正式提供跨设备学习前，还需要实施账号、服务端数据库、同步冲突处理和备份，并测试旧数据迁移。个人备份保存在项目外的「词库备份」文件夹，不提交 GitHub，也不打包进镜像。
