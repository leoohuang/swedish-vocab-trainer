# 瑞典语单词练习工具：开发方案

日期：2026-10-17。原始方案已确认，现已完成本机试用版及 v0.2 AI 整理接口。实际接入状态、配置和限制见 [AI 整理接入](AI整理接入.md) 与 [验证记录](验证记录.md)。以下保留原始规划。

## 1. 产品想法

用户上传自己整理的瑞典语单词笔记，系统把混乱内容整理成可编辑词库；用户选出本轮要学的词，以每组默认 10 个词完成认识、选择、拼写和错词回练，之后按记忆表现安排复习。

建议先做适配手机和电脑浏览器的 Web 应用。暂定目录名 `swedish-vocab-trainer`，产品名称以后再定。

核心流程：上传或粘贴 → 自动整理 → 用户确认 → 建立词库 → 选本轮单词 → 认识与选择 → 拼写 → 错词回练 → 后续复习。

## 2. 调研结论及其边界

- 不背单词官网介绍了语境例句、根据记忆效果调整学习安排、拼写测试。这些可以作为产品方向参考；本方案中的“每组 10 词”和具体关卡是拟议设计，并非已核实的不背单词完整流程。
- Anki 官方手册中的文本导入支持分隔符、字段映射、预览、重复处理。我们的产品可以保留这些可检查的导入机制，再增加对不规则笔记的理解能力。
- Word、文本型 PDF 有现成解析工具；扫描 PDF、截图和手写内容需要另外处理 OCR。提取文本与正确理解词条是两个不同步骤。

来源：

- 不背单词官网：https://www.bbdc.cn/
- Anki 文本导入：https://docs.ankiweb.net/importing/text-files.html
- Mammoth（DOCX 解析）：https://github.com/mwilliamson/mammoth.js
- PDF.js：https://mozilla.github.io/pdf.js/

## 3. 怎样处理混乱文件

第一版建议支持：TXT、Markdown、CSV、XLSX、DOCX、带可选中文字的 PDF，以及直接粘贴文本。旧版 DOC、扫描 PDF、截图和手写识别放到后续版本。表格允许用户指定列或工作表；复杂版式允许分段导入。

示例输入：

```text
今天的生词
en bok - 书，böcker
äta / 吃 / åt / ätit
vacker 美丽的
Jag tycker om kaffe. 我喜欢咖啡。
```

建议整理结果：

| 词条                 | 释义         | 附加信息            | 处理方式                         |
| -------------------- | ------------ | ------------------- | -------------------------------- |
| en bok               | 书           | 原文出现复数 böcker | 保留词性和冠词信息，待确认       |
| äta                  | 吃           | 原文出现 åt、ätit   | 作为同一词条的词形，待确认       |
| vacker               | 美丽的       | 原文无其他词形      | 保留已有信息                     |
| Jag tycker om kaffe. | 我喜欢咖啡。 | 完整句子            | 标为句子，默认不进入单词拼写训练 |

处理分成三步：

1. 文件解析：读出段落、表格及来源位置。去掉明显页眉、空行，但保留可回看的原始片段。
2. 词条整理：规则优先处理整齐数据；复杂段落交给 AI 配对单词、释义、词形和例句，返回固定结构。模型返回后还要校验字段、来源和缺失项。
3. 用户确认：显示“原文 / 整理结果 / 需确认问题”，允许编辑、合并、拆分、删除和批量确认。缺少释义的条目可以保存为草稿，但不能直接出题。

不能明确配对的内容进入待处理列表，不能静默丢弃。重复导入显示差异，由用户决定保留、合并或更新；更新词条时保留已有练习历史。同形异义词、词形和短语不应只凭字符串相似就自动合并。

用户原文与系统补充内容分别标记。若只有瑞典语词、没有释义，可提供 AI 补充草稿，但需要确认；模型自报的置信度不能作为正确性保证。上传文档只当作数据读取，不执行其中夹带的指令。

## 4. 每组 10 个词怎么练

“选词”同时支持两个含义：用户选择本轮学习哪些词；训练中通过选择题认识词义。

| 环节     | 用户操作                         | 系统行为                                 |
| -------- | -------------------------------- | ---------------------------------------- |
| 挑选本轮 | 从未学词、收藏词或待复习词中选取 | 默认 10 个，可调整；不足 10 个直接开练   |
| 初次认识 | 看词义、词形，按需听发音         | 新词简要展示；复习词可跳过此步           |
| 选择热身 | 看瑞典语选释义，再看释义选瑞典语 | 错题展示解释，隔几题再出现               |
| 拼写回忆 | 只看释义，输入瑞典语             | 逐字符显示错漏；支持提示和显示答案       |
| 错词回练 | 再次拼写本轮错词或提示词         | 穿插其他词后再测，避免只记住刚看到的答案 |
| 本轮结果 | 查看独立答对、提示、错误情况     | 更新复习安排，支持退出与稍后继续         |

示例：“书（名词，en）” → 输入 `bok`。冠词单独记录；需要训练冠词时开启“冠词 + 单词”题型，答案为 `en bok`。题目必须明确要求哪种答案。

新词选择题答对，不等于已经会拼写。独立拼写正确、使用提示、看过答案、答错需要分别记录。第一版暂定每词在本轮两次间隔独立拼写正确后标记“本轮完成”；反复出错可先标记困难并结束本轮，避免无限循环。“本轮完成”不等于长期掌握。

选择题从已确认且意义不重叠的词中选干扰项。词库太小或找不到可靠选项时，改成翻卡回忆，不为凑四个选项生成含糊答案。多义词和同义词需限定目标词条或接受确认过的多个答案。

## 5. 瑞典语专项设计

- `å / ä / ö` 默认严格区分，提供屏幕按键；练习模式可提醒缺失变音符号，但不直接当作完全正确。
- 保存 en / ett、词性、常见词形和短语。词形训练单独提问，例如明确要求过去时，不能把所有变形都作为任意题目的正确答案。
- 忽略输入两端空格，规范 Unicode；一般单词默认不区分大小写，专名和特殊题型另行定义。
- 拼写首轮不强制播放语音，避免提前泄露答案；听写模式另开。
- 发音先尝试设备可用的瑞典语语音，缺失时给出明确状态。若需要一致音质，再接入云端 TTS；正式选型时验证浏览器和设备支持。
- 优先使用用户提供的例句；AI 补充例句标记来源并可编辑，不声称是词典或真实语料。

## 6. 复习机制

第一版采用简单、可解释、可调整的间隔规则。例如首次完成后次日复习，独立答对后延长到 3、7、14 天；答错缩短间隔。这是产品初始规则，不宣称是最优算法或对每个人都有效。

每天先展示到期复习，再开始新词。分别记录选择能力和拼写能力；选择正确不能掩盖拼写错误。之后如需引入成熟调度算法，应保留原始答题事件，并明确如何把客观答题表现转成算法需要的评分。

## 7. 第一版范围

建议做完整的小闭环：

- 文件上传与文本粘贴；上述常用格式解析。
- 规则 + AI 整理、原文对照、编辑确认、重复处理。
- 词库管理、默认每组 10 词、选择题、拼写、错词回练。
- 基础复习队列、练习结果与断点继续。
- 本机保存、JSON 完整备份恢复、CSV 词条导出。
- 手机与电脑可用，瑞典语特殊字母输入。

后续版本再增加账号、跨设备同步、扫描件 OCR、听写、词形专项、共享词库。首版不加入社区、排行榜和复杂游戏系统。

本机版适合先验证练习体验；正式面向多用户并提供跨设备服务时，再完成真实登录、数据库权限隔离、备份和同步冲突处理。

## 8. 建议实现结构

以下是待开发时验证的选型建议，不是已经安装或实现的功能：

- 前端：React + TypeScript + Vite；响应式布局。
- 导入：各格式独立解析器，统一输出带来源的文本块，再进入词条整理。
- AI：服务端接口处理复杂整理，密钥只放服务端。规则能够完成的导入不调用模型；设置文件大小、条目数、超时及费用上限，失败后可重试或手工整理。
- 本机数据：IndexedDB 保存词库、学习状态及答题记录；JSON 备份支持恢复。
- 后续云端：根据账号与部署需求选择 Auth、数据库和存储服务；目前不创建付费资源。

拟议数据对象：导入批次、来源片段、词库、词条、练习场次、答题事件、按训练类型区分的复习状态。原始词条与学习状态分开保存，以免修改释义时清空进度。

文件尽量在本地解析；调用云端 AI 前明确说明将发送哪些文字，让用户选择是否启用。默认不长期保存上传原文件；需要回查的来源片段随词条保存。个人文件和练习数据不进入 GitHub。

## 9. 开发顺序与验收

1. 用几份合成的混乱笔记确认整理表结构与交互；后续再用用户愿意提供的真实样本检验。
2. 打通 TXT / CSV / 粘贴 → 确认 → 10 词训练 → 保存 → 再次打开继续的完整路径。
3. 补齐 DOCX / XLSX / 文本型 PDF 与 AI 整理，处理重复、缺失与失败状态。
4. 完成手机适配、复习队列、备份恢复；再决定是否进入账号与云同步阶段。

验收重点：

- 混乱输入要么变成可追溯词条，要么显式进入待处理列表，不静默遗漏。
- 词义和词形不确定时可以修正；未经确认的内容不参与出题。
- 使用提示不计独立答对，答错后可回练，本轮可退出并继续。
- `å / ä / ö` 正确判定，短语与冠词题的答案要求明确。
- 刷新和重复导入不会丢失学习进度；JSON 导出再导入能恢复词库与练习状态。

主要不确定性是文件版式复杂度、AI 整理质量和真实手机端输入体验。先用代表性样本验证，再承诺识别覆盖率和开发工期。

## 10. 当前建议

建议先确认“浏览器应用 + 首版本机进度 + 可选 AI 整理 + 用户确认导入 + 每组 10 词训练”这一范围。确认后再开始应用开发，并用可运行版本逐步验证。GitHub 远程仓库的名称、归属和可见性在实际同步前确定。
